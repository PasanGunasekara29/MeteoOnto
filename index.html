Introduction · Meteorological Ontology

Mete∞nto

Meteorology Knowledge Connected.

Mete∞nto connects the key layers of meteorological data: observations, sensors, and platforms through SOSA/SSN; units through QUDT; time through OWL-Time; places and spatial features through GeoSPARQL and DBpedia; and data collections and provenance through PROV-O. Its own forecasting, geospatial, extreme-weather, and risk modules add domain detail, while SWEET alignments connect atmospheric and hydrological phenomena with environmental science. Together, these links describe what happened, how it was measured, where and when it occurred, and how forecasts and datasets relate.

What is Mete∞nto?

An ontology is a structured set of concepts and relationships with formal, machine-readable definitions. Mete∞nto models meteorological knowledge so weather information from different sources can be described, linked, queried, and reused consistently.

Before you begin

Preliminaries

These basics explain how Mete∞nto represents meteorological knowledge and connects its domain modules to established Semantic Web vocabularies.

◇

Ontologies

An ontology defines concepts in a domain and the relationships between them so people and software can interpret information consistently.

≋

RDF, OWL & Turtle

RDF expresses facts as subject–predicate–object triples. OWL adds formal class and property definitions; Turtle is a readable text format for RDF.

◎

Classes & properties

Classes describe kinds of things, such as observations or sensors. Object properties connect things; datatype properties associate them with values such as numbers or text.

↗

Modules & alignments

Mete∞nto separates core meteorological concepts from forecasting, geospatial, extreme-weather, and risk modules. Alignments connect terms to SOSA/SSN, QUDT, OWL-Time, GeoSPARQL, PROV-O, SWEET, and DBpedia.
