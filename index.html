Introduction · Meteorological Ontology

Mete∞nto

Meteorology Knowledge Connected.

Mete∞nto is a shared, machine-readable model for describing meteorological knowledge. It brings observations, measurements, sensors, datasets, forecasts, places, time, and weather risks into a connected structure—so information from different sources can be described and explored consistently.

What is Mete∞nto?

An ontology defines concepts and relationships in a formal, machine-readable way. Mete∞nto provides a shared vocabulary for describing what weather information represents, how it was observed or predicted, where and when it applies, and how it relates to its source.

Meteorological domain

One model across connected weather domains.

Mete∞nto’s core terms and domain modules describe the entities and relationships needed to bring meteorological information together.

◉

Observations and measurement

Describe observed weather properties, measurement results, values and units, and the sensors or platforms that produced them.

⌁

Forecasts and models

Represent forecast information, predictions, meteorological models, deployments, and the results associated with them.

◎

Places, geometry, and time

Give observations and forecasts geographic context through places, features, geometries, coordinates, time instants, and durations.

△

Extreme weather and risk

Connect hazardous weather events with indicators, affected locations or infrastructure, risk assessments, and response context.

Interoperability

Connected to established Semantic Web vocabularies.

Mete∞nto aligns relevant domain concepts with established vocabularies, helping weather data connect with wider observation, measurement, time, geospatial, provenance, and environmental knowledge.

Introduction · Preliminaries

OWL and RDF concepts behind Mete∞nto.

These foundations explain how the ontology describes meteorological entities, defines their relationships, and connects its modules. The examples of constructs below reflect the MeteoOnto Turtle files unless identified as general OWL features.

Core ontology foundations

≋

RDF, OWL, and Turtle

RDF represents knowledge as triples: a subject, predicate, and object. Together, triples form a graph. OWL adds formal meanings for classes, properties, and logical axioms, allowing software to interpret relationships and derive consequences. Turtle is a compact, readable syntax for writing RDF graphs; prefixes provide short names for long vocabulary identifiers.

◇

Classes, subclasses, and definitions

A class represents a category of entities. In rdfs:subClassOf, every instance of the specific class is also an instance of its superclass. For example, if class A is a subclass of B, membership in A entails membership in B. Equivalent classes have the same members; disjoint classes cannot share members. OWL also supports union and complement class expressions. An equivalence definition can state necessary and sufficient conditions, while a subclass axiom states a necessary condition.

↔

Properties, domains, and ranges

Object properties connect one resource to another. Datatype properties connect a resource to a literal value, such as a number or date; annotation properties add labels, comments, and documentation. Domain and range axioms describe the kinds of resources a property connects. In OWL they support inferences about types, rather than acting as database validation rules. Subproperties, equivalent and inverse properties, and property chains describe additional relationships.

⌘

Property characteristics

OWL can specify how a property behaves: functional means it has at most one distinct value per subject; symmetric means a relationship works in both directions; transitive means a relationship carries through a chain; and irreflexive means no resource relates to itself through that property. MeteoOnto’s Turtle files use these characteristics where appropriate to define meteorological and geographic relations.

⊂

Restrictions and class reasoning

Existential restrictions (someValuesFrom) require at least one relationship to a value of a specified class; universal restrictions (allValuesFrom) limit relationships to values of a specified class. MeteoOnto files use both. OWL also offers value and cardinality restrictions. A reasoner can check logical consistency and classify concepts from these axioms.

◎

Individuals, data, and the open world

Individuals represent particular entities; XML Schema datatypes describe literal values such as strings, decimals, dates, and durations. OWL does not assume that two different names identify different things unless this is stated. Under its open-world assumption, an unstated fact is unknown, not false. Labels, comments, imports, and version metadata help describe and organize ontology files.

How Mete∞nto applies these foundations

▤

Modules and imports

Mete∞nto separates the core model from forecasting, geospatial, extreme-weather, and risk modules. OWL imports and shared identifiers help modules build on the same concepts instead of defining them in isolation.

⌁

Vocabulary alignments

Alignment files relate MeteoOnto classes and properties to established vocabularies using subclass, equivalent-class, and equivalent-property axioms. These links connect meteorological data with SOSA/SSN, QUDT, OWL-Time, GeoSPARQL, PROV-O, SWEET, and DBpedia.

OWL concepts summarized from Horridge, A Practical Guide to Building OWL Ontologies Using Protégé 4 and CO-ODE Tools (2011). The MeteoOnto-specific constructs above were checked against the repository’s Turtle files.
